## How to run the investigation after approval

1. Use temporary database and output folders, synthetic or saved inputs, and simulated services. Make no live NAV or OpenAI requests. Keep the real dashboard data and Yehya’s earlier evidence intact.
2. Run the four cases against the current program **before changing its behaviour**. Save the date, starting Git commit, commands and actual output. For each case, record what happened to each ad, how many AI calls were attempted and what reached the dashboard.
3. If an outcome differs from the expectation, trace the fault from the input or service reply to its effect on the queue and results. Save the failure, make the smallest necessary repair, then repeat the **identical** experiment. If an existing safeguard handles the fault, identify it and record that outcome.
4. After a repair, rerun all four cases and the existing offline evaluation. The evaluation command is `python eval/run.py --mode offline-suite --suite eval/cases/manifest.json`. Preserve the fixed inputs, references, prompt and scoring rules.
